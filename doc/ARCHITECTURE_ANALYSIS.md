## 2. What the AWS Amplify Gen 2 Standard Actually Is

The official `create-amplify` CLI and every AWS tutorial place the `amplify/`
directory **at the root of the frontend project** — the same folder that holds
`package.json`, `app.json`, and source code. For a React Native / Expo app:

```
my-expo-app/          ← git root = project root
├── amplify/          ← backend lives here, alongside the frontend
│   ├── auth/resource.ts
│   ├── data/resource.ts
│   ├── backend.ts
│   ├── package.json
│   └── tsconfig.json
├── app/              ← Expo Router screens
├── components/
├── ...
├── package.json      ← single package.json at repo root
├── app.json
├── eas.json
└── amplify_outputs.json  (gitignored — generated by npx ampx sandbox)
```

Key rules from the Amplify Gen 2 docs:
- `amplify/` must be a sibling of the root `package.json`.
- `npx ampx sandbox` and `npx ampx pipeline-deploy` are always run from the
  same directory that contains `package.json`.
- `amplify_outputs.json` is written to that same root directory and imported
  from there in the frontend code.

The current project violates all three rules because everything sits one level
inside `mobile/`, not at the repo root.

---

## 3. Why the `mobile/` Sub-folder Is a Problem

| Symptom | Cause |
|---|---|
| CI must always set `working-directory: mobile` | No root package.json |
| Developers must `cd mobile` before any `npm` or `npx ampx` command | Code not at root |
| IDE tooling (ESLint, TypeScript, Expo) doesn't pick up config automatically | Config files not at root |
| EAS Build requires extra path configuration | `app.json` not at root |
| `amplify_outputs.json` is generated inside `mobile/`, not the git root | Wrong working directory |

A `mobile/` sub-folder makes sense **only** in a monorepo that also contains a
`web/` or `backend/` sibling. There is no such sibling here, so the nesting
adds friction with no benefit.

```yaml
name: CI
on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main, develop]

# No defaults.run.working-directory needed
jobs:
  quality:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
      - run: npm ci
      - run: npm run lint
      - run: npx tsc --noEmit
```

## 5. Recommended Structure — Option B: Monorepo (Future-Proof)

**Use this only if a web app or shared packages are planned in the near term.**

```
bacuy-new/
├── .github/
├── apps/
│   ├── mobile/               ← Expo app
│   │   ├── amplify/          ← backend lives inside the mobile app
│   │   ├── app/
│   │   ├── ...
│   │   └── package.json
│   └── web/                  ← Next.js or React app (future)
│       ├── amplify/          ← or reference the mobile amplify outputs
│       └── package.json
├── packages/
│   └── shared-types/         ← shared TypeScript types (future)
├── doc/
├── BACUY_SPEC.md
├── CLAUDE.md
├── package.json              ← root workspace (npm workspaces or pnpm)
├── turbo.json                ← Turborepo config
└── .gitignore
```

This option requires adding Turborepo (`npm install --save-dev turbo`) and
configuring `workspaces` in the root `package.json`. It is significantly more
complex and is **not recommended** unless there is a concrete plan for a second
app within 3–6 months.

---

## 6. Recommendation

**Adopt Option A (flat structure).**

Rationale:
- It matches the official Amplify Gen 2 project layout exactly.
- All developer tooling works from the repo root with no `cd` required.
- CI becomes simpler — no `working-directory` override.
- EAS Build, `npx ampx sandbox`, and `npx ampx pipeline-deploy` all work
  without configuration overrides.
- The app is mobile-only; the `mobile/` nesting exists for no current reason.

---

## 7. Migration Steps

1. Move all contents of `mobile/` to the repo root:
   ```
   # from bacuy-new/
   xcopy mobile\* . /E /H /Y
   rmdir /S /Q mobile
   ```
2. Delete the `working-directory: mobile` default from `.github/workflows/ci.yml`.
3. Update the `cache-dependency-path` in CI from `mobile/package-lock.json` to
   `package-lock.json`.
4. Verify `lib/amplify.ts` still imports `amplify_outputs.json` with a relative
   path (`./amplify_outputs.json`) — this should still be correct after the move.
5. Run `npx ampx sandbox` from the repo root to confirm the backend wires up.
6. Run `npx expo start` from the repo root to confirm the frontend starts.

> **Note on `amplify_outputs.json`:** This file is gitignored and
> machine-generated. After the move, delete any copy inside `mobile/` and
> regenerate it by running `npx ampx sandbox` from the new root.
