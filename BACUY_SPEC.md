# Bacuy App — Product Specification & Design Document

## Overview

Bacuy is an intelligent personal productivity app that goes beyond a traditional to-do list. Its core philosophy is **frictionless capture**: the user records anything freely, and the app organizes it intelligently. Records can be tasks, habits, skills, attitudes, or projects — each with its own lifecycle and tracking mechanism.

---

## 1. Core Concept: Free-Form Capture

The entry point is a single, blank, distraction-free input where the user writes anything — a thought, a task, a reminder — without having to decide upfront where it belongs. After capture, the app (with AI assistance) suggests and assigns the right category, tags, and context.

**Flow:**
```
User writes freely → AI classifies → User confirms/adjusts → Record is organized
```

---

## 2. Record Categories

| Category | Description |
|---|---|
| **Habit** | Recurring behaviors to build or reinforce (e.g., "Kiss my partner every morning") |
| **Skill** | Goals requiring progressive tracking (e.g., "Learn to play cuatro") |
| **Attitude** | Mindset commitments based on personal values (e.g., "Always do my best") |
| **Project** | Multi-level work broken into sub-activities and tasks |
| **Standard Task** | One-off to-dos, errands, or specific items |

## 3. Feature Specifications

### 3.1 Habit Tracking

- Log each habit occurrence with contextual metadata:
  - Location
  - Time of day
  - Companions present
  - Mood / emotional state
  - Prior activities (trigger chain)
- Streak tracking with visual progress indicators
- Habit templates (e.g., "50 Wedding Promises" list)

### 3.2 Skill Development

- Progress milestones and checkpoints
- Session logging (duration, notes, outcome)
- Year-end goal framing with periodic review reminders

### 3.3 Attitude Records

- Linked to personal value systems or frameworks (e.g., Toltec agreements)
- Reflection prompts to reinforce the attitude
- Situation tagging: when and how the attitude was applied

### 3.4 Project Management

- Hierarchical breakdown: Project → Sub-activities → Tasks
- Each task can have: due date, time estimate, assignee (self or others), result criteria
- Status tracking: pending, in-progress, blocked, done
- Timeline view and priority ordering

### 3.5 Smart Alarms & Reminders

| Type | Description |
|---|---|
| **Time-based** | Fixed time (e.g., "Every day at 7:00 AM") |
| **Location-based (Geofence)** | Triggered on arrival/departure (e.g., "When I get home, remind me to…") |
| **Smart/Relative** | Natural language rules (e.g., "The business day before the 15th of each month") |

### 3.6 Voice Input

- Wake word activation for hands-free capture
- Voice-to-text transcription with AI post-processing for classification
- Audio playback of pending tasks (Alexa-style interaction)

### 3.7 Intelligent Grouping

- Auto-categorization of tasks into life areas: Work, Health, Home, Finance, Personal Growth, etc.
- Priority scoring based on deadlines, importance, and energy required
- Smart scheduling suggestions based on available time windows

### 3.8 Multilingual Support

- Full i18n support from day one
- Initial languages: Spanish and English
- All UI strings, notifications, and AI prompts must be localizable

## 4. Data Architecture

### 4.1 Backend: AWS Amplify

All data management and authentication will be handled through **AWS Amplify**, leveraging:

- **Amazon DynamoDB** — NoSQL data store for all user records
- **Amazon Cognito** — User authentication and authorization
- **AWS AppSync** — GraphQL API layer (auto-generated by Amplify)
- **AWS Lambda** — Business logic for smart alarm rules and AI classification triggers
- **Amazon Location Service** — Geofence management for location-based reminders
- **Amazon SNS / EventBridge** — Push notifications and scheduled event delivery

### 4.2 Core Data Models (DynamoDB via Amplify)

```graphql
type User @model @auth(rules: [{ allow: owner }]) {
  id: ID!
  email: String!
  preferredLanguage: String
  lifeAreas: [String]
  records: [Record] @hasMany
}

type Record @model @auth(rules: [{ allow: owner }]) {
  id: ID!
  rawInput: String!           # Original free-form text
  category: RecordCategory!   # HABIT | SKILL | ATTITUDE | PROJECT | TASK
  title: String
  description: String
  status: RecordStatus        # PENDING | IN_PROGRESS | DONE | ARCHIVED
  lifeArea: String
  priority: Int
  dueDate: AWSDateTime
  alarms: [Alarm] @hasMany
  habitLog: [HabitEntry] @hasMany
  subItems: [Record] @hasMany  # For project hierarchy
  parentId: ID               # Self-referencing for sub-tasks
  tags: [String]
  createdAt: AWSDateTime
  updatedAt: AWSDateTime
}

type Alarm @model @auth(rules: [{ allow: owner }]) {
  id: ID!
  recordId: ID!
  type: AlarmType             # TIME | GEOFENCE | SMART
  scheduledAt: AWSDateTime
  geofenceId: String
  smartRule: String           # e.g., "LAST_BUSINESS_DAY_BEFORE:15"
  isActive: Boolean!
}

type HabitEntry @model @auth(rules: [{ allow: owner }]) {
  id: ID!
  recordId: ID!
  completedAt: AWSDateTime!
  location: String
  mood: String
  companions: [String]
  notes: String
}
```

## 5. Authentication

- **Provider:** Amazon Cognito via AWS Amplify Auth
- **Methods:** Email/password, Google OAuth, Apple Sign-In
- **Features:** MFA support, password reset, session management
- **Authorization:** All records are owner-scoped using Amplify's `@auth(rules: [{ allow: owner }])` directive — no user can access another user's data

## 6. Suggested Technology Stack

### 6.1 Recommendation: React Native + Expo

**Why:**
- Single codebase for iOS and Android (and optionally web)
- Expo's managed workflow accelerates setup and OTA updates
- Strong AWS Amplify SDK support (`@aws-amplify/react-native`)
- Large ecosystem for the features required: voice input, geolocation, notifications, offline support

### 6.2 Full Stack

| Layer | Technology | Reason |
|---|---|---|
| **Mobile App** | React Native + Expo | Cross-platform, Amplify-compatible |
| **State Management** | Zustand | Lightweight, simple API |
| **Navigation** | Expo Router (file-based) | Clean routing, deep link support |
| **API / Data** | AWS AppSync + Amplify DataStore | Real-time sync, offline-first |
| **Auth** | AWS Cognito via Amplify Auth | Secure, scalable, built-in UI components |
| **Database** | Amazon DynamoDB (via Amplify) | Scalable NoSQL, auto-synced |
| **AI Classification** | Amazon Bedrock or OpenAI API | Free-form input → structured record |
| **Voice Input** | Expo Speech / `react-native-voice` | Wake word + transcription |
| **Notifications** | Expo Notifications + Amazon SNS | Push alerts, scheduled reminders |
| **Geofencing** | Expo Location + Amazon Location Service | Location-based alarms |
| **Localization** | `i18next` + `react-i18next` | Full i18n support |
| **Styling** | NativeWind (Tailwind for RN) | Consistent, fast UI development |

### 6.3 Alternative: Flutter

If native performance and a single consistent UI are priorities, **Flutter** is the next best option. However, AWS Amplify's Flutter SDK is less mature than the React Native SDK, so custom integrations would require more effort.

## 7. Key User Flows

### 7.1 Capture & Classify
```
1. User opens app → lands on blank input screen
2. Types or speaks a thought
3. AI suggests: category, life area, priority, due date
4. User confirms or adjusts
5. Record saved to DynamoDB via AppSync
```

### 7.2 Habit Check-In
```
1. Alarm fires (time or location-based)
2. User marks habit as done
3. App prompts for context: mood, location, companions
4. Entry logged → streak updated → insights generated
```

### 7.3 Project Breakdown
```
1. User creates a Project record
2. Adds sub-activities (recursively)
3. Assigns due dates and priority to leaf tasks
4. Views project timeline / progress board
```

## 8. Non-Functional Requirements

| Requirement | Detail |
|---|---|
| **Offline-first** | Amplify DataStore syncs when connectivity is restored |
| **Performance** | List screens must render < 200ms on mid-range devices |
| **Security** | All data owner-scoped; no cross-user data access |
| **Privacy** | Voice data processed ephemerally; not stored |
| **Scalability** | DynamoDB auto-scales; no server management needed |
| **Availability** | AWS-backed 99.9%+ uptime target |
